# Prompt 结构模式

好的 prompt 通常不是「更长」，而是「结构更清楚」。几个可复用的骨架。

## 骨架一：角色 + 上下文 + 任务 + 约束

```
你是一名资深前端工程师。（角色）
我们在做一个内部管理系统，技术栈 React 19 + Vite。（上下文）
请把下面这段 class 组件改写为函数组件。（任务）
要求：保持 Props 类型不变；不要引入新的依赖。（约束）
```

## 骨架二：给出输入输出的例子

比描述格式更有效的是直接给一个样例。模型会模仿样例的粒度。

```
输入：user_id=42
输出：{"id": 42, "name": "..."}
```

## 常见反模式

:::danger 尽量别这么写

- 「写得好一点」——没有可判定的标准
- 一次塞进五个不相关的任务
- 只在最后加一句「不要胡编」，但没给可引用的资料

:::

## 用思考顺序引导

对推理型任务，把步骤写进 prompt 比让它自由发挥更稳定：

```
请按以下步骤回答：
1. 先列出已知条件；
2. 指出信息不足之处；
3. 再给出结论。
```
