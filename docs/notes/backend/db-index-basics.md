# 数据库索引入门

索引的本质：把「全表扫描」换成「按序定位」。代价是写入变慢、占额外空间。

## 最左前缀原则

联合索引 `(a, b, c)` 能命中的查询：

| 查询条件 | 是否命中 |
| --- | --- |
| `a = 1` | ✅ |
| `a = 1 AND b = 2` | ✅ |
| `a = 1 AND b = 2 AND c = 3` | ✅ |
| `b = 2` | ❌ |
| `a = 1 AND c = 3` | ⚠️ 只用到 `a` |

## 什么情况索引会失效

:::warning 常见失效场景

- 在索引列上做运算或函数调用：`WHERE YEAR(created_at) = 2026`
- 隐式类型转换：字符串列传数字，或反之
- 以 `%` 开头的模糊匹配：`LIKE '%foo'`
- `OR` 连接了未建索引的列

:::

```sql
-- ❌ 索引失效
SELECT * FROM orders WHERE YEAR(created_at) = 2026;

-- ✅ 改成范围查询，索引可用
SELECT * FROM orders
WHERE created_at >= '2026-01-01' AND created_at < '2027-01-01';
```

## 排查顺序

1. `EXPLAIN` 看 `type` 和 `key`，确认是否真的走了索引；
2. 看 `rows` 估算行数，数量级不对说明统计信息过期；
3. 联合索引顺序按「等值条件在前、范围条件在后」排列。
