## 一条常用的推进顺序

```text
静态侦察（架构 / 壳 / 导入表）
    ↓ 看不出东西？
让程序跑起来（环境先通，再谈分析）
    ↓
找锚点（界面文案 → 字符串 → 引用点）
    ↓
读懂分支结构（cmp + jcc 的分岔口）
    ↓
选改动粒度（NOP / 改比较 / 注入 stub）
    ↓
验证（离线自检 → 单点验证 → 集成）
```

每一步都可能失败，失败的原因往往不在这一步本身——**环境不通、编码猜错、命中多处、副本只打了一半**。笔记里记的坑比方法多，这是有意的。
